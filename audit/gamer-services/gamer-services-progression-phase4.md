# Progression trust qualification — GS-AUDIT-P4

Continues Phase 3, not a new inventory/security audit. Reviewed the complete supported operation allow-list in server `Service.cpp`, progression handlers `Leaderboards.cpp`, `Avatars.cpp`, profile/review handlers and their native callers. Public mutable title data is distinguished from derived account/ranking data and operator provisioning. No generic anti-cheat, TrueSkill solver, entitlement economy or game-specific score rule was introduced.

The local FNA tree has the ABI reference but no GamerServices/Net implementation to prove Xbox console behavior. Supplemental local `../xna4-spec` and `../xna4-decomp/reference/xna4/decompiled/windows` show `AwardAchievement(string achievementKey)` and a writable signed `long` `LeaderboardEntry.Rating` plus typed columns. The title was the reporter; the public award carries neither completion time nor incremental progress. These references support API shape, not undocumented Xbox backend internals. CNA intentionally implements provisioned title-managed claims. Being the source of a plausible score is **not itself a CNA defect**.

Local OS-readable/modified save files are not tamper-resistant competitive authority.

## End-to-end awards

Public `AwardAchievement`/Begin → guest/catalog and lifetime checks → backend chooses account token → JSON key → current authentication/title → provisioned key + token-bound owner → transactional INSERT OR IGNORE → server-generated ticks/outcome → list joins catalog and own earned row → native Achievement collection/notification at completion. Extra foreign userId cannot redirect the write. Reused request IDs return the original success outcome; a new-ID duplicate returns awarded=false and preserves the first ticks. Public API timestamp semantics need no change: server timestamps were already used in Phase 3. Only the offline competing-duplicate path needed a fix.

Qualification extends Phase 3 with malformed/negative/oversized/decreasing/future extras, duplicate retrieval/first timestamp, another account remaining unearned, unauthenticated requests, raw NaN/Infinity/overflow JSON, unknown/cross-title boards, latest rollback, best in both directions/ties, concurrent best writes and two-user derived ranks. Final `service_progress_trust`: **111 checks**.

## Session/result eligibility

A nonarbitrated score needs the owner's valid **local gameplay epoch**, not a live network session. This models a title reporting local account statistics and does not pretend to verify a match. Supplying another person's userId without that participant credential fails.

Ranked reports need a real server-created Lobby→Playing round and its saved participant/machine list. Nonexistent sessions/rounds and never-joined reporters fail. A participant may report another **actual round participant** by design; machines compare reports rather than only submit their own score. Wrong round targets and contradictory reports fail. The immutable historical grant survives disconnect or deletion, explicitly required by migration `010_ranked_arbitration.sql`; completion of an ended game must not require the session to stay alive. Tests leave participants, delete the directory session, accept legitimate old participants and still reject an outsider. The accepted write can be replayed unchanged without rewriting the round. Final `service_arbitration`: **62 checks**.

Resolution is CNA majority agreement over machines that reported each row, including bounded timeout resolution; it is not Xbox TrueSkill, full-participant unanimity, gameplay observation, skill-based matchmaking or a cryptographic proof of a match. No additional generic scoring restrictions were justified by the evidence.
