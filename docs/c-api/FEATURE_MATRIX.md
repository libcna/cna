# CNA C API 0.1 Feature Matrix

## Scope

This matrix describes the implemented experimental `0.1.0` C ABI. It is a usable initial 2D
vertical slice, not complete CNA or XNA coverage. [`COVERAGE.md`](COVERAGE.md) remains the
source-symbol mapping record and will grow into the complete public-surface inventory.

All declarations are available through the C17 umbrella header `CNA/C/cna.h`. Public structures
use fixed-width C fields and versioned structure prefixes where evolution is expected. All
fallible calls return `CNA_Result`; no C++ or Sharp Runtime type or exception crosses the ABI.

## Implemented surface

| Family | Implemented operations | Current boundary |
|---|---|---|
| ABI | Encoded ABI query through `cna_get_abi_version` | Experimental version `0.1.0`; no stability promise before the release gate |
| Errors | Per-thread result, category and UTF-8 diagnostic count/copy | Diagnostics are replaced by the next failed ordinary call; programs branch on `CNA_Result` |
| Gamepad capabilities | Controller type identities and the complete capabilities value: 35 readable and writable flags plus the type, a canonical-default initializer, and a per-slot read on the game thread | A value, not a handle, because the canonical type is a copyable snapshot; an empty slot reports the canonical disconnected value rather than failing; connection always agrees with the gamepad state snapshot |
| Gamepad values | Button set and directional pad over the existing button mask, thumbstick and trigger values, and the snapshot's constructors, component projections, comparisons, hash and text | One representation per value — the pad is the mask's four directional bits and the analog values are the snapshot's analog block; the thumbstick constructor square-clamps and the trigger constructor clamps; trigger equality is an epsilon comparison; the snapshot carries a single button mask, so a supplied pad is merged into it |
| Gamepad device queries | Vibration and trigger vibration, light bar, gyro and accelerometer, device player index get/set, power info, button labels, GUID/name/path/serial count-copy, firmware version, Steam handle, connection state, touchpad count/finger-count/finger, and the pure axis dead-zone exclusion | Every query needs the game thread of a running game, because CNA is event-driven; an empty slot answers false, zero, empty or `Unknown` rather than failing; a sensor query reports availability separately from its reading, so "no sensor" is not an error |
| Keyboard values and queries | Snapshot construction from an explicit key set, the key-state indexer, comparison, hash and text; per-slot capture, modifier state, scancode translation and both key-name families with reverse lookup | An out-of-range key is refused rather than silently dropped, unlike the canonical constructor; every slot reports the same snapshot because CNA has one keyboard; an unknown key name answers `CNA_KEY_NONE`, not a failure |
| Mouse values and queries | Snapshot construction, comparison, hash and exact text; window handle, position, relative mode, capture, global position and warp; the static clicked event as an owned registration plus a raise route and the test reset | Construction takes a button bit set, not five ordered button arguments; the window handle is an opaque value the API never dereferences; an unsatisfiable request answers false rather than failing; the clicked subscription belongs to the process, and the reset drops it so a later release is a no-op |
| Mouse cursors | Owned cursor handles: the empty cursor, all twelve stock identities, a texture-derived cursor, disposal, release and making one active | A stock handle is a borrowed view of a process-lifetime singleton, so releasing it never frees the shared cursor and disposing it is a no-op; no `SDL_Cursor` is ever exposed, so the raw-pointer constructor and accessor have no C mapping |
| Text input | All three `TextInputEXT` events as owned registrations with one shared release route, a raise route for each, the opaque bound window handle, plain and typed start, stop, the activity and screen-keyboard queries, the IME input rectangle and the test reset | The subscriptions belong to the process, so none takes a game handle; composition text and candidate lists cross as UTF-8 views borrowed only inside the callback; an above-BMP code point arrives as two surrogate calls; `start`/`length` and `selected` are forwarded verbatim exactly as the canonical dispatch does; an undefined input-type identity is refused rather than falling back to plain text; with no window bound every activation is a successful no-op and every query answers false |
| Touch and gestures | The gesture type bit set and the gesture sample value; touch location construction, pressure-blind comparison, hash and text; touch collection construction and the whole mutation surface over the existing fixed snapshot; every `TouchPanel` static including display metrics, orientation, enabled gestures, the gesture queue, slot writes, the frame advance and the test reset | One representation per value — the collection is the existing eight-slot snapshot, so an append beyond it is refused rather than dropping a touch; equality, the hash and the text all ignore the pressure extension and the text carries only the position; reading an empty gesture queue is refused, not answered with a default sample; a raised touch event feeds gesture detection rather than the snapshot and is dropped entirely until a display size is published; the reset clears the display metrics and window handle too |
| Haptics | Device enumeration with identifier and name, opening standalone or from a joystick or the mouse, joystick and mouse capability probes, and an owned device handle carrying open state, name, capabilities, effect support, the simple rumble, the create/update/run/stop/free effect lifecycle, effect status, gain, autocenter, pause, resume, disposal and release; plus the feature bit set and the direction, effect and capability values with their comparisons | Opening never fails for want of hardware — it returns a real handle that reports itself closed, and every route on a closed device answers false, zero or -1 rather than failing; rumble strength, gain and autocenter are passed to the platform unvalidated; a custom waveform travels beside the effect value rather than inside it, so the value owns no heap; the device name is read through count/copy rather than living in a POD; freeing an unknown effect is a successful no-op; no `SDL_Haptic` is ever exposed |
| Raw joysticks | Device enumeration with descriptor and name, capabilities and both device strings by identifier, an owned captured snapshot with a count/copy pair for axes, buttons, hats and trackballs plus snapshot comparison and release, the type and hat-position identities, the descriptor and capability values with their comparisons, both hot-plug events as owned registrations with one shared release route and a raise route each, and the test reset | The snapshot is an owned handle rather than a fixed value, because the canonical arrays have no maximum and one capture must answer from one instant; a hat position is an identity, not a composable bit set; an unconnected identifier answers with the disconnected defaults and empty strings rather than failing, and a power percent of -1 means unknown rather than empty; the device name and GUID are read through count/copy rather than living in a POD, so the capability comparison takes both strings; the enumeration reports the devices the native layer holds open and is valid only until that set changes; trackball motion is relative, so capturing consumes it; no `SDL_Joystick` is ever exposed |
| Host sensors, device enumeration, clipboard and power | The sensor kind identity, the sensor and input-device descriptor values with their comparisons, sensor enumeration and both host readings, mouse/keyboard/touch-device enumeration with names, all four device hot-plug events as owned registrations with one shared release route and a raise route each, the test reset, clipboard read/write/presence, and host power state with remaining runtime and charge | Both sensor reads report availability separately and leave the reading untouched when nothing answered; device enumeration is metadata only, because XNA input state stays merged across devices, and its identifier is 64-bit where the sensor and joystick ones are 32-bit; the clipboard setter reports that the request was made, not that the platform honored it, and the clipboard is process-external state another application can change between two calls; a power value of -1 means unknown rather than none left |

An enumerated renderer identity is not a support claim. Applications must query graphics, touch
and audio capabilities and handle `CNA_RESULT_NOT_SUPPORTED`; future platform work must add
appropriate C evidence before this table claims support. The strict-C suite holds itself to the
same rule: no test branches on a renderer identity, so adding a backend needs no test edits.

## Ownership and call context

| Object/value | Lifetime rule |
|---|---|
| Game | Owned handle; destroy exactly once on its creation thread |
| Callback game | Borrowed for the active callback; callback code must not destroy it |
| Graphics device | Borrowed from the callback game and invalid immediately after that callback |
| Graphics-resource event registration | Owned handle; callback/context remain caller-owned until unsubscription; may be unsubscribed after resource destruction |
| Graphics-device event registration | Owned handle that does not block game destruction; the runtime invalidates live subscriptions once the device has been disposed, so the handle stays releasable afterwards |
| Texture2D | Owned standalone or game child that survives callbacks; game children are destroyed before their game |
| Texture3D / TextureCube | Owned game child that survives callbacks; destroy before its game; RenderTargetCube uses its own typed destroy route |
| VertexBuffer / DynamicVertexBuffer | Owned game child; copied declaration; destroy before game; ContentLost registration may be released after buffer destruction |
| IndexBuffer / DynamicIndexBuffer | Owned game child; fixed 16/32-bit width; destroy before game; ContentLost registration may be released after buffer destruction |
| EffectAnnotation / EffectAnnotationCollection | Owned creation-thread-affine metadata handles; collection insertion and lookup copy values; returned annotations outlive their source collection |
| EffectParameter / EffectParameterCollection | Owned creation-thread-affine mutable handles; element aliases and nested views retain stable native storage; each assigned texture-overload slot blocks that resource's disposal/destruction until cleared or released |
| EffectTechnique / EffectPass and collections | Owned creation-thread-affine handles or stable element aliases; nested pass/annotation views and returned elements retain native storage across collection growth/destruction |
| Effect / EffectMaterial / ShaderEffect / SpriteEffect | Owned game child; destroy before game unless live descendant views retain it; descendants transitively retain the effect/game ownership; bound shader textures remain retained per sampler unit until replacement or final descendant release |
| BasicEffect / DirectionalLight | BasicEffect is an owned game child; assigned Texture2D handles are retained independently by each clone; standalone lights are ordinary owned handles and nested light views transitively retain the parent effect/game |
| AlphaTestEffect / DualTextureEffect / EnvironmentMapEffect | Owned game children; each same-device Texture2D or TextureCube slot retains its C resource independently across clones; EnvironmentMapEffect directional-light views transitively retain their parent effect/game |
| SkinnedEffect | Owned game child with copied 72-matrix palette; its same-device Texture2D is retained independently across clones and nested light views transitively retain the parent effect/game |
| ColorMatrixEffect / PbrEffect / SkinnedPbrEffect | Owned game children; each PBR same-device Texture2D slot is retained independently across clones, SkinnedPbr owns a copied 72-matrix palette, and nested light views transitively retain the parent effect/game |
| ModelBone / ModelBoneCollection | Owned creation-thread-affine stable nodes and live collection views; parents retain children, returned aliases share mutation, and weak parent metadata avoids dangling parents after hierarchy release |
| ModelMeshPart / ModelMeshPartCollection | Owned creation-thread-affine shared parts and retained snapshots; indexed aliases share mutation; assigned Effect/VertexBuffer/IndexBuffer resources remain owned by their original handles and are protected from early disposal/destruction |
| ModelMesh / ModelMeshCollection / ModelEffectCollection | Owned game-child meshes and owned live/snapshot views; parts, parent bones, meshes and same-device effects are retained transitively; releasing the final mesh owner safely detaches independently retained parts |
| Model | Owned creation-thread-affine aggregate or empty standalone handle; immutable collection/root aliases retain bones and meshes; registered C resource context is released on replacement, clearing or final destruction |
| MorphTargetDataEXT | Owned creation-thread-affine handle with deep-copied descriptors; a ModelMeshPart retains attached data independently of the original data handle; all returned arrays remain caller-owned copies |
| SpriteBatch | Owned child that survives callbacks; destroy before its game |
| Submitted texture | Retained by an active batch until successful `End` or batch destruction; destruction while retained is refused |
| RenderTarget2D / RenderTargetCube | Owned game child; unbind and destroy before game; RenderTarget2D also satisfies Texture2D C operations |
| SpriteFont | Owned game child; destroy before game and before its retained source Texture2D/RenderTarget2D |
| Game callbacks/context | Table is copied; function pointers and context remain caller-owned and valid through game destruction |
| POD values and output buffers | Caller-owned; inputs are copied for the call and no output API writes a partial array |
| Keyboard snapshot | Independent copied POD; it has no handle or game lifetime after capture |
| Mouse/gamepad/touch snapshot | Independent copied POD; it has no handle or game lifetime after capture |
| ContentManager | Owned game child; destroy before game; unload/destroy does not destroy issued C resources |
| Content-loaded Texture2D | New owned game child per successful load; remains valid after manager unload/destruction |
| Session event registration | Weakly tied to its session; release unsubscribes; releasing after the session is gone is a no-op |
| NetworkSession | Standalone owner of the caller-owned pointer canonical creation returns; one at a time; destroy after every borrowed gamer view |
| SignedInGamer | Standalone owner; retained while published in the process-wide collection, and released only after it is cleared |
| AvailableNetworkSession | Standalone owner; copies of it are independent, including elements copied out of a collection |
| AvailableNetworkSessionCollection | Standalone owner; copies its input, so source handles stay independently owned |
| NetworkGamer | Standalone owner, or a borrowed view onto a machine's roster; a view is released before its machine |
| NetworkMachine | Standalone owner; destroy after every borrowed gamer view taken from it |
| NetworkSessionProperties | Standalone owner; destroy after every enumerator over it |
| Session-property enumerator | Owned list child; observes the live list; destroy before its list |
| PacketWriter / PacketReader | Standalone owners; independent of any session; destroy explicitly |
| ContentReader | Standalone owner; borrows a storage stream and closes it on destroy; the stream handle is still released separately |
| Content type reader | Standalone owner; independent of any reader or manager; destroy explicitly |
| StorageDevice | Standalone owner, not a game child; destroy after every container it opened |
| StorageContainer | Owned device child; destroy before its device and after closing every stream it opened |
| Storage stream | Owned container child; close before its container; no Sharp Runtime stream is exposed |
| SoundEffect | Owned game child; copied PCM survives input buffer; destroy after all instances and before game |
| SoundEffectInstance | Owned effect/game child; destroy before effect; no C callback/context is retained by mixer |

Game, graphics, texture, batch, content and snapshot-capture calls use the game creation/graphics
thread. Pure keyboard/gamepad/touch snapshot and normalization helpers are documented for any
thread.

## Error and capacity behavior

- Null pointers, invalid structure prefixes, reserved fields, enum values and numeric ranges return
  `CNA_RESULT_INVALID_ARGUMENT`.
- Null, stale, wrong-kind and expired borrowed handles return `CNA_RESULT_INVALID_HANDLE` or the
  documented state failure for an out-of-context borrow.
- Wrong-thread native operations return `CNA_RESULT_THREAD` before touching thread-affine state.
- Unsupported renderer or initial-slice functionality returns `CNA_RESULT_NOT_SUPPORTED` when a
  callable operation reaches that native limitation.
- Count/copy APIs always report the required count. Insufficient capacity returns
  `CNA_RESULT_BUFFER_TOO_SMALL` and does not write a prefix.
- Native exceptions are translated at the boundary. Unexpected native failures become
  `CNA_RESULT_INTERNAL`; no exception crosses into C.

## Intentionally unavailable in 0.1

The following families are planned work, not implicitly supported and not permanent exclusions:

- the remaining typed content asset routes;
- remaining audio (file/content loading, fire-and-forget, globals/3D, streaming, microphone and
  XACT), plus media and video;
- remaining window, platform, service, event and runtime APIs;
- player-indexed keyboard capture, input mutation/events, gamepad control/capabilities/extensions
  and touch display/gesture/event APIs;
- remaining 3D resources and draws, consumption of completed vertex/index-buffer and binding
  values, skinned-model/animation-player data, and remaining stock effects;
- occlusion queries and remaining graphics-device operations;
- Texture3D, TextureCube and renderer-specific successful non-Color transfer evidence;
- SpriteBatch matrices, effects and text drawing;
- advanced and renderer-specific CNA extensions not listed in the implemented table.

Until the generated inventory and completion gates in `plan_binding.md` are finished, any public
CNA symbol not explicitly represented in [`COVERAGE.md`](COVERAGE.md) is unimplemented.
