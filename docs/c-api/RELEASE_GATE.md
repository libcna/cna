Generated by `tools/c-api/check_release_gate.py` from `tools/c-api/release_gate.json`.

**Release:** CNA C ABI 0.9.0, experimental

This gate governs publishing an **experimental** C ABI release. ABI 1.0 -- the point at which only additive changes are permitted within a major version -- is a separate decision that this gate does not make and must not be read as making.

## Why each one is here

### ✅ The compatibility matrix is real, current and honest

*Evidence:* docs/c-api/COMPATIBILITY.md, gated by CApiCompatibilityMatrix and CApiHeaderCompatibility

C99 is a verified floor rather than a claim: the matrix found and killed a duplicate typedef that made C99 impossible.

### ✅ No unreviewed ABI break

*Evidence:* tools/c-api/abi_baseline.json, gated by CApiAbiHeaderBaseline and CApiAbiBaseline

The header half needs no build and runs everywhere; the export half runs in each C API build tree.

### ❌ No public C++ symbol is unaccounted for

*Evidence:* docs/c-api/COVERAGE.md, gated by CApiCoverageMatrix

Closed by CBIND-044 on 2026-08-16, reopened the same day by the merge of `next`, and closed again by CBIND-047 and CBIND-049. The second merge of `next` reopened it on 2026-08-17, and CBIND-050 found the first closure had been partly an illusion: 73 mapping rules matched a whole header with `.*`, so 121 symbols the merge added inherited "implemented and tested" without a single C route existing for them. Rules are now pinned to the stable IDs they were reviewed against, which is why this reopened at 176 rather than 55. CBIND-051A through CBIND-051E bound every one of them -- the KHR material extensions on both PBR effects, the glTF import report and its diagnostics, the mesh-part and clip target-space families, the model's cameras, skins, bounds and material variants, and the animation-player additions -- with a single row recorded not applicable, a `CNA::Internal` entry point that reaches a public header. An unapproved partial row still fails this criterion, and so does a rule that grows past what it was approved for. The third merge of `next` (2026-08-17) reopened it again, at 12 rows: the compiled Effect Framework campaign and the IGL renderer. `CBIND-052A` closed 3 of them -- the `IGL` and `PIXIJS` renderer identities and the `CompiledEffects` capability -- and found that a fourth, `TINYGL`, had been recorded implemented since an earlier merge with no C constant existing for it at all, because `CBIND-050` seeded its approvals from the pre-merge tree and so grandfathered that tree's own false claim. The remaining 9 are the `Effect`, `EffectParameter`, `EffectPass` and `EffectTechnique` members the compiled-effect work added or reshaped, and `CBIND-052B` owns them. This criterion is recorded not met until then, which is the whole point of measuring it rather than remembering it. `CBIND-052B` then bound all 9: `Effect::Clone()` and `OnApply()` stopped being pure virtual, which made the C adapter's Clone() override -- correct when there was nothing to inherit -- silently drop a compiled effect's runtime and parameter values, so the override is gone; `GetCompiledRuntimePtr` became `cna_effect_get_is_compiled_ext`, the one fact a C caller can act on, since the runtime object is renderer-owned implementation; the three `EffectParameter` const overloads are answered by the routes that already answer their non-const twins; and the two reflected constructors became `_ext` siblings rather than growing published routes, with their runtime indices readable back. The owner ruled on 2026-08-17 that `EffectPass`'s index should get the public C++ accessor its `EffectTechnique` counterpart already had rather than be recorded as a partial, so the row is bound in full and the partial count stays at 12. The merge of `origin/modern` into `next` on 2026-08-20 expanded the public CNAEXT engine surface and reopened this criterion at 1402 planned rows. The merge integration binds the six closed renderer and capability identities, leaving 1396 planned rows; this criterion remains recorded not met until those rows receive C routes or approved dispositions.

### ✅ The package carries the native libraries CNA builds

*Evidence:* the CNACApi install component, proved by CApi_InstalledConsumer

Ruled on by the project owner on 2026-08-16: the package ships them. FFmpeg stays a system dependency for reasons that are not convenience -- redistribution terms, soname freezing against security updates, and the transitive libraries a distribution build was linked against. CApi_InstalledConsumer now passes no -rpath-link and no LD_LIBRARY_PATH, so a regression here fails a test rather than surprising a consumer.

### ✅ A static configuration that keeps the same ABI promise

*Evidence:* tools/c-api/generate_static_archive.py and CNA::CApiStatic, proved by CApi_InstalledConsumer

Ruled on by the project owner on 2026-08-16: build it. The objection that stopped it before was real -- an archive carries every object it swallowed -- so the archive is not simply ar'd together: the closure is partially linked into one relocatable object and every symbol that is not part of the ABI is localized, with the build failing outright if any non-cna_* symbol other than an unlocalizable STB_GNU_UNIQUE C++ static survives. The same hello_cna.c is built both ways from the installed package and both are run.
