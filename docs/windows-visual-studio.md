# Windows development with Visual Studio and VS Code

CNA uses one checked-in CMake preset contract for Visual Studio, VS Code, command-line builds and
Windows CI. There is no hand-maintained solution or project file. Visual Studio may either open the
source directory through its CMake integration or open the solution generated by the Visual Studio
2022 preset; VS Code uses the same Ninja/MSVC presets through CMake Tools.

This support was added on 2026-10-30. The preset contract and its local configuration tests pass,
and `.github/workflows/windows-msvc-ci.yml` now supplies an automatic native-MSVC baseline. No
successful run of that new workflow is recorded from this Linux checkout yet, so this page does not
upgrade the native-Windows qualification claims in [`../handoff.md`](../handoff.md) §5.2.

## Prerequisites and checkout layout

Install Visual Studio 2022 with the **Desktop development with C++** workload, a Windows SDK, Git,
CMake 3.21 or newer, and Ninja. The project itself still accepts CMake 3.20 for direct non-preset
configures; CMake 3.21 is required to read the repository's preset schema. VS Code users should
install the extensions recommended by `.vscode/extensions.json`.

Every build needs Sharp Runtime as a sibling checkout. The SDL_GPU and HEADLESS presets do not need
the `easy-gl` or `meta-gl` siblings:

```text
work/
├── cna/
└── sharp-runtime/
```

Initialize CNA's top-level submodules before configuring a test build:

```powershell
git -C cna submodule update --init
```

This supplies SDL3, SDL3_mixer, GoogleTest and the other pinned dependencies. Do not use a source
ZIP: it cannot contain Git submodules. The first SDL-enabled configure builds the vendored SDL
libraries into `.sdl-prebuilt-Windows-*`; later build trees reuse that install only when its
source, patches, generator, platform, toolset, compiler, configure arguments and MSVC CRT still
match its manifest.

## Presets

| Configure preset | Purpose | Generator |
|---|---|---|
| `windows-msvc-headless-debug` | SDL-free compiler and portable-contract baseline | Ninja + MSVC, Debug |
| `windows-msvc-sdlgpu-debug` | Native SDL3/SDL_GPU development and smoke tests | Ninja + MSVC, Debug |
| `windows-msvc-sdlgpu-relwithdebinfo` | Optimized SDL_GPU build with symbols | Ninja + MSVC, RelWithDebInfo |
| `windows-vs2022-sdlgpu` | Conventional multi-configuration generated solution | Visual Studio 17 2022, x64 |

Matching build and test presets carry the same names. The Visual Studio generator has separate
`windows-vs2022-sdlgpu-debug` and `windows-vs2022-sdlgpu-relwithdebinfo` build/test presets because
its configure tree contains both configurations.

The MSVC runtime is explicit and consistent across CNA, Sharp Runtime and vendored SDL:
`MultiThreadedDebugDLL` in Debug and `MultiThreadedDLL` otherwise. A project may deliberately
override `CMAKE_MSVC_RUNTIME_LIBRARY`; doing so changes the SDL manifest and rebuilds the shared
prebuilt rather than silently mixing CRTs.

## Visual Studio: open the CMake project

Use **File → Open → Folder** and select the CNA source directory. Choose
`windows-msvc-sdlgpu-debug` (or the headless preset) in Visual Studio's CMake preset selector,
configure it, then select a target to build or debug. CMake's target `FOLDER` properties group the
generated view under `CNA/Libraries`, `CNA/Renderers`, `CNA/Tests`, `CNA/Examples`, `CNA/Tools`,
`CNA/Applications` and `CNA/Build`; dependencies have their own group.

Visual Studio's CMake integration is the recommended edit/build/debug route. CMake owns the build
tree, compiler switches and target graph, so do not add a parallel `.vcxproj` or commit IDE-local
configuration files.

## Visual Studio: generate a solution

For workflows that specifically require a `.sln`, configure the multi-configuration preset from a
normal PowerShell or Developer PowerShell:

```powershell
cmake --preset windows-vs2022-sdlgpu
cmake --build --preset windows-vs2022-sdlgpu-debug
ctest --preset windows-vs2022-sdlgpu-debug
```

Open `cmake-build-windows-vs2022-sdlgpu/CNA.sln`. It is generated output: change CNA's CMake files
or presets and regenerate it instead of editing the solution or projects by hand. The
RelWithDebInfo build and test presets select that configuration without needing another configure.

## VS Code

Start VS Code from an x64 Visual Studio Developer PowerShell/Command Prompt so Ninja can find
`cl.exe`, then open the CNA directory. The checked-in workspace settings make CMake Tools consume
`CMakePresets.json` and provide IntelliSense through the selected CMake target. Choose a Windows
preset with **CMake: Select Configure Preset**, configure, then use CMake Tools' target selector and
**Debug** command. No repository `launch.json` is needed for normal executable targets.

The equivalent terminal sequence is:

```powershell
cmake --preset windows-msvc-sdlgpu-debug
cmake --build --preset windows-msvc-sdlgpu-debug
ctest --preset windows-msvc-sdlgpu-debug
```

For the compiler-only/portable contract, replace the preset name with
`windows-msvc-headless-debug`. The SDL_GPU test preset forces SDL's `windows` video driver and
Direct3D 12 GPU driver. CTest reports an unavailable device as a skip; the automatic CI workflow
additionally rejects any such skip so it cannot pass without running the smoke programs.

## Application runtime files

Source-tree and installed C++ SDK consumers use the same deployment call after defining and
linking their executable. For an installed-package consumer:

```cmake
find_package(CNA CONFIG REQUIRED)
add_executable(MyGame main.cpp)
target_link_libraries(MyGame PRIVATE CNA::CNA)
cna_deploy_runtime(MyGame)
```

`cna_deploy_runtime()` copies the selected SDL3/SDL3_mixer DLLs, a renderer-owned runtime such as
wgpu-native, and dynamic MinGW runtime DLLs where applicable. It is exported by the
`CNA_INSTALL_CXX=ON` package and is a no-op for configurations with no runtime payload. Repeated
calls on one target are ignored.

## CI and evidence boundary

`.github/workflows/windows-msvc-ci.yml` runs automatically for pushes and pull requests to
`next`, `develop` and `main`:

- the headless job configures, builds `CnaTests`, and runs the portable platform/audio/configuration
  contract without SDL;
- the SDL_GPU job builds the focused eight-program smoke set and runs it through SDL's Direct3D 12
  driver, failing on a CTest skip.

`d3d-windows-ci.yml` remains a manual focused qualification for `DIRECTX9` and SDL_GPU, and the
Windows platform-module job in `platform-ci.yml` remains manual. A hosted-runner smoke is not a
full real-hardware qualification. Current gaps remain: the full renderer pixel suite on native
Windows, relocated installed-SDK execution on Windows, the non-ASCII `TEMP` limitation of the
content test corpus, and the Windows wgpu-native package (`WEBGPU-1`). See
[`../handoff.md`](../handoff.md) §5.2.

## Troubleshooting

- If Ninja cannot find `cl.exe`, reopen the terminal through Visual Studio's x64 developer shell.
- If a preset is hidden, confirm the host is Windows; Windows presets are intentionally
  host-filtered.
- If SDL is rebuilt, read the configure reason. A compiler, toolset, generator, CRT, patch or
  configure-argument change is intentionally a cache miss.
- Keep build trees separate by preset. Do not point Debug, RelWithDebInfo, Ninja and Visual Studio
  generator profiles at the same binary directory.
- To force a dependency rebuild, remove only the exact `.sdl-prebuilt-Windows-*` directory named
  by the configure. It is shared by compatible build trees.
