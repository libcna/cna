## 1. Provenance — the original history is never the casualty

**P1. Every original head is preserved before adaptation begins.** An immutable, GPG-signed,
annotated archive tag must exist and verify **before** the first commit of that lane is adapted.
Pattern: `archive/preintegration/<lane-slug>-<YYYYMMDD>`. The tag message records logical lane,
original ref, original head SHA, merge base, the adaptation checkpoint, and an explicit statement
that it preserves original pre-integration history. 22 such tags exist (inventory §9); one is
outstanding (EasyGL `rvc`, inventory §7.5).

**P2. Never destructively rewrite the only copy of an original branch history.** Adaptation produces
**new** commits on the integration branch. The original branch ref is left exactly as it was. If a
lane's original ref and its archive tag are the only two references to a history, neither may be
moved, deleted or force-updated.

**P3. Do not check out an original feature branch in a shared worktree merely to inspect it.** Use
`git show`, `git log`, `git diff`, `git range-diff`, `git merge-base`, `git rev-list`. Read-only
detached inspection only when genuinely necessary.

**P4. One writing agent per worktree.** The integration worktree
`/rv/data/development/github.com/openeggbert/cnaintegration` has exactly one writer at a time.

**P5. Every adapted lane ships a `range-diff`.** `git range-diff <archive-tag>...<adapted-range>`
is produced and recorded on the lane card. Differences must be confined to author, committer,
trailers, signature, and any commit explicitly recorded as dropped or recomposed. An unexplained
content difference is a defect in the adaptation, not an acceptable variance.

**P6. Dropped or recomposed commits are recorded with their reason.** A commit omitted because the
checkpoint already supersedes it is a decision, and it is written down on the lane card — with the
superseding commit named. Silent omission is indistinguishable from an accident.

## 2. Attribution — what must never appear

The final integrated history **must not contain AI attribution** in commit subjects, bodies,
trailers, author fields or committer fields.

**Banned tokens** — searched over `%s`, `%b`, `%an`, `%ae`, `%cn`, `%ce` for every adapted commit:

```
CC OK · Claude · Claude Code · Anthropic · Co-authored-by: Claude
generated by · authored by · bot · agent · AI · agent-status text
```

**Claude must not appear as author, co-author, committer or contributor** introduced by the
integration process. Not in a trailer, not in a body, not in a `Co-Authored-By:`, not in a
`Claude-Session:` URL.

### 2.1 What is *not* a violation

**Literal Git ref names are factual provenance identifiers, not contributor attribution.** These
stay, verbatim, wherever a lane's origin is recorded:

```
claude/html-dom-cna-backend-xefzwf
origin/claude/cna-magnum-gr-backend-211xsx
origin/claude/wicked-engine-cna-backend-5ffqzd
```

**Do not confuse a branch name with an authorship claim.** Erasing these would destroy the ability
to trace an integrated commit back to the ref it came from.

**The filename `CLAUDE.md`** is a real tracked file in this repository. `feature/metal`'s four regex
hits are all references to it. A commit message that says "document X in CLAUDE.md" is describing a
file, and is clean.

### 2.2 Narrative prose still has to go

`feature/gl` is 100 % Robert-authored and fully signed, yet five commit bodies carry process
narrative: *"decision, not autonomous agent action"*, *"found another agent already implemented…"*,
*"…(commit 14109db, co-authored by…)"*, *"reconcile with other-agent commits"*.

These are not trailers and not authorship claims — they are prose about how the work was produced.
They are still rewritten out. The technical content of each message is preserved; the process
narration is not. This is the **MESSAGE CLEANUP REQUIRED** class.

## 3. Authorship of adapted commits

**A1. Preserve legitimate human authorship where the original history supports it.** A commit
authored by Robert Vokac stays authored by Robert Vokac, with its original author date.

**A2. Never invent a third-party author.** If the original author is not a real human contributor,
the adapted commit is authored by **the configured human maintainer identity** — for this repository
`Robert Vokac <robertvokac@robertvokac.com>`. No placeholder, no pseudonym, no fabricated
contributor.

**A3. 187 commits across 11 lanes are authored and committed by `Claude <noreply@anthropic.com>`.**
Every one is re-authored under A2. Full breakdown in inventory §5; the total-cleanup lanes are
`opengl4` (28/28), `magnum` (13/13), `wicked` (10/10), `depthcrt` (6/6) and `ext` (1/1).

**A4. Every adapted commit is GPG-signed.** 204 of the 796 original commits carry no signature at
all; after adaptation the count is zero. **`--no-gpg-sign` must never be used.** Signing key
`FB9CE8E20AADA55F`; `commit.gpgsign` is already `true`, and `git tag -s` is passed explicitly
because `tag.gpgsign` is not set.

**A5. `html-dom` needs signature-only treatment for 17 commits.** They are authored and committed by
Robert Vokac, carry no attribution text, and are simply unsigned. Author and message are preserved
unchanged; only the signature is added. This class must not be conflated with A3 — rewriting their
authorship would be wrong.

## 4. Form of adapted commits

**F1. Clean technical commit messages.** State what changed and why. No process narration, no status
text, no session identifiers.

**F2. Logical grouping.** Prefer the original commit boundaries where they are already logical —
most lanes here are linear runs of finished, well-scoped commits with **zero merges and zero
WIP/fixup/squash subjects across all 21 lanes**. Recompose only where the original grouping is
genuinely poor, and record the mapping on the lane card.

**F3. Reference the originating task ID** where the original message did (`D2D-87`, `GLB-38`,
`WICKED-32`). These are project task identifiers and are worth keeping.

**F4. Match the surrounding history's conventional-commit style** — `feat(scope):`, `fix(scope):`,
`docs(scope):`, `test(scope):`.

**F5. No merge commits into the integration branch during adaptation.** Lanes are adapted as
replayed, cleaned commits, not merged. This keeps `range-diff` meaningful.

## 5. History-class classification

Each lane is classified before adaptation and the class determines the work required.

| Class | Meaning | Required action |
|---|---|---|
| **HISTORY CLEAN** | Human-authored, fully signed, no attribution text | Replay commits; re-sign only if the rebase changes them. `skia`, `direct2d`, `gdi`, `glide`, `gltf`, `opengl2`, `opengl1`, `stub`, `metal` |
| **MESSAGE CLEANUP REQUIRED** | Clean authorship and signatures; process narrative in bodies | Rewrite bodies (§2.2), preserve author and technical content. `gl` |
| **SIGNATURE-ONLY CLEANUP** | Human-authored, clean text, unsigned | Add signature; change nothing else. `html-dom` (17 commits) |
| **AUTHOR/TRAILER CLEANUP REQUIRED** | Non-human author/committer, trailers, usually unsigned | Re-author under A2, strip trailers, sign. Total: `opengl4`, `depthcrt`, `ext`, `magnum`, `wicked`. Partial: `llgl`, `diligent`, `sokol`, `html-dom`, `dxold`, `opengles1` |
| **SQUASH/RECOMPOSITION REQUIRED** | Original grouping is not publishable as-is | Recompose with a recorded mapping. No lane is currently in this class on grouping grounds; `depthcrt` recomposes 6→5 only because one commit is **dropped as superseded**, not because its grouping is poor |
| **DEPENDENCY-FIRST** | Blocked on a rebase or an external revision | `magnum`, `wicked` (24-commit rebase onto the checkpoint) |
| **CROSS-REPOSITORY** | Requires another repository's `develop` first | `gl` — MetaGL then EasyGL, inventory §7.4 |
| **REIMPLEMENT/ADAPT LOGICALLY** | History cannot be replayed usefully | No lane is currently in this class |

A lane may hold more than one class. `html-dom` holds three at once (21 clean-signed, 17
signature-only, 17 author/trailer).

## 6. Prohibited operations

Never, in any repository touched by this campaign:

- `git stash` / `git stash pop` — **four pre-existing user stashes exist and are not this campaign's
  to touch**, inspect, drop or rewrite
- `git reset --hard`
- `git clean -xfd`
- force push
- destructive history rewriting of an original branch
- `--no-gpg-sign`
- `git add -A` / `git add .` — stage by explicit filename; this repository routinely carries
  unrelated pre-existing local changes
- creating a worktree under `/tmp`, `/var/tmp` or `/dev/shm`

**Pushing is not part of adaptation.** Commits, branches and tags produced by this campaign are
local until the owner asks for them to be pushed, and **no integrating session pushes anything**.

**Corrected 2026-08-04.** The original wording — *"Every one of the 22 archive tags, the integration
branch, and this session's documentation commits are local and unpushed"* — has since been overtaken
by an owner push. Measured with `git ls-remote`: `feature/audit` (`047c254a`),

This changes nothing about the rule — an integrating session still never pushes — but it does change

## 7. Per-lane adaptation checklist

1. Confirm the lane's archive tag exists, targets the recorded head, and **verifies**.
2. Confirm the original ref still points at that head. **If it has moved, stop and report** — do not
   silently re-derive.
3. Confirm no dependency (C1/C2 in `INTEGRATION_ORDER.md`) is outstanding.
4. Classify the history (§5) and record the class on the lane card.
5. Apply the `GpuDrawParams` adaptation for `fc0dd2a2` where the lane needs it — 19 of 21 do.
6. Apply the post-audit backend obligations where the lane adds a backend:
   `RequireFaithfulDeclarationEXT` at draw time, truthful `WireFrame` reporting, header-only helper
   (`INTEGRATION_ORDER.md` §1.1).
7. Adapt commits: re-author, strip trailers, clean messages, sign.
8. Build and test per the lane's test matrix. **Grep the complete log for failures — never a
   truncated tail.**
9. Produce `git range-diff` against the archive tag; attach it to the lane card.
10. Search the adapted range for every banned token (§2); expect zero hits.
11. Verify every adapted commit's signature.
12. Confirm the original ref and archive tag are still unchanged.
13. Re-check the `REMED-CONTENT-007`/`-008` conditional blocker for this specific lane
    (`INTEGRATION_ORDER.md` §6).

## 8. Verification commands

```bash
# archive tag intact and signed
git tag -v archive/preintegration/<lane>-<date>

# original ref unmoved
git rev-parse refs/heads/feature/<lane>

# provenance
git range-diff archive/preintegration/<lane>-<date>...<adapted-head>

# attribution sweep — expect no output
git log --format='%H%n%s%n%b%n%an <%ae>%n%cn <%ce>' <base>..<head> \
  | grep -inE 'CC OK|Claude|Anthropic|Co-authored-by|generated by|authored by|\bbot\b|\bagent\b|\bAI\b'

# signature sweep — expect only G or U
git log --format='%G? %h %s' <base>..<head>
```

Note that `%G?` reports **`U`** for this project's normal state: a good signature from an
uncertified key. `U` is a pass. **`N`** is no signature and is a fail. **`E`** means the signature
could not be checked — in this repository that is an SSH-signed commit hitting the unconfigured
`gpg.ssh.allowedSignersFile`, and it must be resolved rather than counted as either.
