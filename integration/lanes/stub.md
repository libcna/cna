## 3. Why ADAPTATION and not DIRECT MERGE

`stub` was classified at the Batch 0 closeout as a **direct-merge candidate**: smallest remaining
lane, 5/5 maintainer-authored, 5/5 maintainer-signed, no history cleanup, no `GpuDrawParams` cost.
**Every one of those history claims re-verified true.** The lane's *history* needs nothing.

Its *content* does. The lane forked from `develop` at `ac3aaaeb` and is 827 commits behind the
integration head, and in that interval two `IGraphicsBackend` members became **pure virtual**:

| Member | Introduced for | Effect on `stub` |
|---|---|---|
| `IVertexBufferBackend::SetVertexDeclaration(const VertexDeclaration&)` | declaration fidelity — *"each implementation must make an explicit decision to use or ignore a declaration, so a newly added backend cannot silently discard one"* | `StubVertexBufferBackend` is **abstract** |
| `IGraphicsBackend::SetRenderTargets(const RenderTargetBindingDescriptor*, int)` | *"Every backend must explicitly consume or reject cube-face descriptors; there is deliberately no compatibility default that could flatten a cube to RenderTarget2D or face +X"* | `StubGraphicsBackend` is **abstract** |

Both are pure *by design*, precisely so a backend cannot inherit a silently-wrong default. Proven by
compiler, not inferred: a `-fsyntax-only` instantiation of all five concrete Stub classes against the
integration head's `IGraphicsBackend.hpp` reports exactly these two, and nothing else.

**A direct merge would therefore have produced a tree that does not compile.** Phase-4 conditions
**7** (no semantic conflict), **8** (no stale API reintroduced) and **10** (§1.1 resolved) fail.
Conditions 1–6, 9, 11 and 12 all hold.

The lane is bounded and repairable, so ADAPTATION was taken, in the `adapt/dxold` shape: replay the
clean originals unchanged, then **one** bounded interface-adaptation commit.

## 4. The exact Stub contract — established from the tree, not from the name

Stub is **a deterministic no-op placeholder backend**. It is *not* diagnostic, *not* state-recording,
and *not* a rasterizer. `docs/stub-backend.md` states it directly: *"the smallest possible complete
`IGraphicsBackend` implementation: every method either does nothing or returns a fixed/trivial value,
with **no bookkeeping of any kind** — no counters, no validation, no trace log, no resource
registry."*

| Question | Answer |
|---|---|
| Must succeed | The whole public surface. A real `Game` — `VertexBuffer`, `IndexBuffer`, `BasicEffect`, `SpriteBatch`, plain and indexed 3D draws — runs to completion **without throwing**. This is the backend's purpose, not a tolerance |
| Must reject | **Nothing.** Stub has no rejection contract |
| Rasterizes | **No.** `Clear`/`Present`/`Draw*` are empty bodies |
| Presents | **No.** `Present()` is an empty body |
| Allocates native resources | **No.** No SDL window, no SDL video subsystem, no GPU library, no pixel or vertex storage |
| Capability reporting | `SupportsCapability()` returns **`false` unconditionally**, for every capability |
| Preserves public object/state semantics | **Partially, and honestly.** Handles answer their *own* getters truthfully — `GetVertexCount`, `GetIndexCount`, `IsThirtyTwoBit`, `GetWidth`, `GetHeight`, and the virtual-resolution round-trip. Nothing else is retained |
| vs **Headless** | Headless is a *state-recording* backend — argument validation, structured trace log, resource-lifecycle/leak tracking, draw-call counters, three strictness modes. Stub has none of it. Headless also **inherits** `SupportsCapability`'s default `true`; Stub overrides to `false` |
| vs **Null** | Naming only. `Stub` was chosen over `Null` because `NULL` is a `<cstddef>`/`<cstdlib>` macro and `CNA_GRAPHICS_BACKEND=NULL` risks silent macro substitution |
| vs **Software** | Software is a genuine CPU rasterizer producing real, correct pixels. Stub produces none |

Its three declared uses: a minimal reference implementation of `IGraphicsBackend`, the fastest
"does the game loop even run" smoke check, and a genuinely dependency-free placeholder backend.

## 5. The §1.1 obligation — decided on evidence, not waved through

§1.1 binds every lane that adds a backend. `stub` adds one, so it applies. All three parts were
resolved explicitly.

### 5.1 Declaration-fidelity guard (`REMED-GFX-DECL-GUARD`) — **not applicable; explicit override required**

The obligation is scoped, in §1.1's own words, to *"a backend with a **native vertex layout**"*.
Measured across the tree, `RequireFaithfulDeclarationEXT` is called by exactly the backends that bind
one: D3D9, D3D11, D3D12, Vulkan, WebGPU, SDL_GPU, Software, Dx2, Dx3, Dx5, Dx6, Dx7, Dx8. **Headless
— the other non-rasterizing backend — does not call it**, and implements
`void SetVertexDeclaration(const VertexDeclaration&) override {}`.

Stub keeps no vertex storage and binds no native layout, so it holds nothing a declaration could
describe unfaithfully; the draw-time guard has no subject. It takes Headless's shape: an **explicit**
empty override, which is the decision the pure virtual exists to force.

### 5.2 Truthful `WireFrame` reporting (`REMED-GFX-209` / `WEBGPU-115`) — **already satisfied, and stricter than Headless**

The lane's fifth commit already made `SupportsCapability` return `false` unconditionally. For a
backend that renders nothing, `false` is the truthful answer. Headless reaches `true` for `WireFrame`
only by inheriting `IGraphicsBackend`'s default — exactly the inherited-default problem that commit
set out to fix. **Stub's report is the more truthful of the two and is kept as-is.**

### 5.3 "Refuse polygon topologies before queueing" — **not applicable to this backend**

`REMED-GFX-209` records the contract as **per backend, not universal**, and gives it three honest
shapes: a positive pixel oracle, a negative oracle where the backend refuses, and *"an **honest skip**
where the backend has no pixel route to measure at all"* — Headless's class.

The refusal requirement exists to prevent an **over-report** failure: a backend that accepts a
wireframe request and returns a frame byte-identical to Solid, silently lying about geometry (WebGPU's
pre-`WEBGPU-115` defect). **Stub returns no frame at all**, so there is no wrong result to prevent.

Refusing would also *break* the backend's declared contract: `examples/stub_smoke_test.cpp` asserts
that plain and indexed 3D draws and a `SpriteBatch` draw all complete without throwing, which is the
entire point of a dependency-free run target. Accordingly `WireFrameTriangleOracle.hpp` deliberately
leaves `CNA_WIREFRAME_PIXEL_ORACLE` undefined for `CNA_BACKEND_STUB`, and the oracle tests do not
exist in this configuration.

### 5.4 One consequence that had to be fixed

`GraphicsDeviceCapabilityTest.WireFrameCapabilityReportIsThisBackendsOwn` is compiled
**unconditionally**, and its `#else` arm asserts `EXPECT_TRUE(reported)`. Stub reports `false`, so an
unlisted backend fails there — the lane's fifth commit targeted `DoesNotSupportWireFrame`, a single
universal assertion that `REMED-GFX-209` has since replaced with this per-backend contract.

Stub gains its own arm asserting `EXPECT_FALSE`, in the **DX1 shape** ("no 3D pipeline at all, so a
true report cannot be backed by any rendering path"), with the reasoning above recorded in place.
This is a **test-contract clarification**, not a production defect, and per the session's rules is
deliberately not raised as a remediation ticket.

## 7. The one conflict, and why a naive resolution would have destroyed work

`cmake/BackendSelection.cmake` conflicted in two hunks — the cache `STRING`/`STRINGS` pair and the
`_cna_explicit_backend_selection` predicate. Both are pure registration boilerplate, and both
required a **union**, never a side choice:

- taking the lane's side would have deleted `dxold`'s eight backends (DX1, DX2, DX3, DX5, DX6, DX7,
  DX8, D3D10) and reverted the `DX3 → FREEDIRECT` rename;
- the lane's `DX3` token means *free-direct*, which `dxold` renamed to `FREEDIRECT`. The head's `DX3`
  is the **real** DirectX 3 backend. The two spellings are not the same backend, and a textual
  preference for either side would have silently conflated them.

Resolved by keeping the head's complete backend set and inserting `STUB` after `SOFTWARE`. Verified
by counting every `dxold` token before and after: `FREEDIRECT` 6→6, `DX1` 11→11, `DX2` 8→8, `DX3`
15→15, `DX5` 8→8, `DX6` 9→9, `DX7` 8→8, `DX8` 7→7, `D3D10` 8→8. **Nothing lost.** All five STUB
registration sites present.

This is the third time in the campaign that a "low-conflict" lane's shared file needed a union rather
than a resolution — the same lesson `ext` taught against `depthcrt`.

**Backend identity: no collision.** `Stub` is inserted mid-enum, which shifts the ordinals of later
backends. `GraphicsBackendType` declares no explicit values, is never cast to an integer, and is
never serialized — it is a `constexpr` compile-time identity, resolved per build. The shift is inert.
