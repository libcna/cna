# glTF to `SkinnedModelEXT` converter

`convert_avatar.py` converts a skinned glTF 2.0 binary (`.glb`) into the content format
`ContentManager` loads as `Microsoft::Xna::Framework::Graphics::SkinnedModelEXT`: an
`.skinnedmodel.json` manifest with a `.skeleton.bin`, per-part vertex/index buffers, a neutral
per-part texture, and one `.clip.bin` per animation. It is an offline tool, not part of the C++
build and never run by CNA at runtime.

It has nothing to do with the standard XNA avatar API. `AvatarDescription`, `AvatarAnimation` and
`AvatarRenderer` use the original CNA avatar catalog generated by
`tools/avatar_builder/generate_avatar_catalog.py` (see `docs/avatars.md`); this converter is for
games that want their own skinned characters through the generic `SkinnedModelEXT` extension.

## Usage

Requires `pygltflib` and `Pillow` (`pip install pygltflib Pillow`).

```
# body, skeleton, and every animation embedded in the same .glb
python3 convert_avatar.py --body character.glb --out content/character --embedded-clips

# or animations from separate .glb files that share the body's joint names
python3 convert_avatar.py --body character.glb --out content/character \
    --clip walk.glb Walk --clip jump.glb Jump
```

Clip names become the names in `SkinnedModelEXT::Clips`. Tracks are retargeted by joint name, so a
separate clip file must use the body's joint names.

Only use source content you are licensed to redistribute in converted form. CNA itself ships no
content produced by this tool.

## What the conversion guarantees

- **Bone order.** Joints are reordered topologically so every parent precedes its children
  (`ComputeBoneTransformsEXT` relies on `parent[i] < i`); `inverseBindMatrices` and every vertex's
  `JOINTS_0` indices are remapped to the new order (`joint_index_remap`).
- **Bind pose.** `bind_pose_local` is derived from the inverse bind matrices by inversion, so it
  cannot disagree with them. glTF's column-major matrices and CNA's row-major ones are
  byte-identical for the same transform, so no transpose is applied.
- **Part names** come from each mesh's name.

These were verified against a hand-built synthetic glTF fixture and against generated content
loaded and rendered through `ContentManager` (`ContentManagerSkinnedModelTests.cpp` covers the
C++ reader).
